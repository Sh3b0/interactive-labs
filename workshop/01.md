# Navigating the Environment

## Terminal

- The terminal environment uses [Fish](https://fishshell.com/) shell running in [Zellij](https://zellij.dev/documentation/) terminal workspace. Terminal sessions are automatically recorded with [asciinema](https://asciinema.org/).

- Once you `exit` the terminal (Ctrl+D), the recording is saved to a local `recordings` directory named according to the start time. We provide a service "Studio" to process recordings (preview, rename, merge, and download).

## Workspace

Your workspace is the home directory (`~`) of the lab terminal. It's the space intended for performing tasks, configuring containerized apps, persisting files across environment restarts, and sharing files with host if needed.

- The default `docker-compose.yaml` creates the volume `./workspace:/home/ubuntu` for the workspace to be accessible (and writable) from host.

- To share files between host and guest in VM mode, create a directory on host at `~/shared` and specify a writable `mount` in `labenv.yaml` with a `mountPoint` like `/home/ubuntu/shared`.

### Initial Workspace Content

- `.config`: config files for fish, zellij, asciinema, and code-server. Customize as needed.
- `recordings`: asciinema `.cast` files for recorded terminal sessions.
- Symlink to `workshop` directory with the `.md` files of the content you're reading.

## External environment

If you prefer to use your host's environment (or any remote host), simply install an SSH server on the host (e.g., `sudo apt install openssh-server`) then connect to it from lab terminal. Some environment variables are set in the container-mode of `labenv` to help with that.

```bash
HOST_WORKDIR     # Path on the host where the labenv container was started
HOST_USERNAME    # Username of the host machine
NETWORK_GATEWAY  # Network address of the bridge to contact the host from container
```
